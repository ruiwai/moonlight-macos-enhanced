Source: https://github.com/AlkaidLab/pyrowave

Exact source file:

`MLPyrowaveMetalShaders.h` extracts only the exact `idwt_msl_source` (FP32)
and `wavelet_dequant_msl_source` raw strings, including comments/whitespace.
They are compiled as **separate** libraries because helper names collide.
No FP16, encoder, upstream parser/API or runtime parser dependency is imported.
The pinned generated header says it was generated by `shaders/metal/transpile.sh`
from `shaders/idwt.comp` and `shaders/wavelet_dequant.comp`; those mathematical
sources carry Hans-Kristian Arntzen's 2025 copyright and MIT SPDX attribution.
The generated shader strings themselves lack inline SPDX notices; this tracked
notice records their provenance rather than asserting an MIT-only fork license.

## Pipeline-creation stage only

The adapter accepts the actual renderer device; it never creates a default one.
It requires macOS 13 / MSL 3.0, Apple7, device width >=128, same-device pipelines,
dequant SIMD width 32 and >=128 threads, both IDWT variants >=64 threads, and
static threadgroup memory within the device limit. Fast math is explicitly OFF.
IDWT constant 0 is false for intermediate passes, true for final DC shift.
The sampler is normalized nearest min/mag/mip with mirror-repeat S/T/R.

This is not format/dimension/aggregate-budget/final-feature preflight or GPU
correctness proof. No buffers, textures, command encoding, dispatch, selection,
network or renderer wiring is implemented. Bounded resource pools, validated-input
dequant + IDWT encoding, last-reader lifetime and pixel validation are later gates.
Initial SDR 8-bit uses `RangeScale = 1`; this is not a claim of limited-range
equivalence, which must be checked with encoder/reference/color evidence later.
The standalone actual-device test checks only pipeline creation and limits; an
unavailable supported GPU is an explicit skip, not a pass. No runtime corpus,
decode dispatch, pixel validation or local build/runtime result is claimed here.
