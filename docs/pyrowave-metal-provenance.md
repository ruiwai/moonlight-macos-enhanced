# PyroWave Metal pipeline provenance and scope

Source: https://github.com/AlkaidLab/pyrowave
Revision: `cc91cbf6363721d19d135d05ca8e3d8665ea6afd`.
Exact source file:
https://github.com/AlkaidLab/pyrowave/blob/cc91cbf6363721d19d135d05ca8e3d8665ea6afd/metal/shaders/pyrowave_msl.h

`MLPyrowaveMetalShaders.h` extracts `idwt_msl_source` (FP32) unchanged and
`wavelet_dequant_msl_source` with a minimal local grid.z batching adaptation:
the existing 24-byte Registers ABI padding holds `block_layer_stride`; grid.z
advances the block-table base and every output layer, including sparse writes.
They are compiled as **separate** libraries because helper names collide.
No FP16, encoder, upstream parser/API or runtime parser dependency is imported.
The pinned generated header says it was generated by `shaders/metal/transpile.sh`
from `shaders/idwt.comp` and `shaders/wavelet_dequant.comp`; those mathematical
sources carry Hans-Kristian Arntzen's 2025 copyright and MIT SPDX attribution.
The generated shader strings themselves lack inline SPDX notices; this tracked
notice records their provenance rather than asserting an MIT-only fork license.

## Pipeline-creation stage only

The adapter accepts the actual renderer device; it never creates a default one.
It requires macOS 13 / MSL 3.0, Apple7, device width >=128, same-device pipelines,
dequant SIMD width 32 and >=128 threads, both IDWT variants >=64 threads, and
static threadgroup memory within the device limit. Fast math is explicitly OFF.
IDWT constant 0 is false for intermediate passes, true for final DC shift.
The sampler is normalized nearest min/mag/mip with mirror-repeat S/T/R.

This is not format/dimension/aggregate-budget/final-feature preflight or GPU
correctness proof. No buffers, textures, command encoding, dispatch, selection,
network or renderer wiring is implemented. Bounded resource pools, validated-input
dequant + IDWT encoding, last-reader lifetime and pixel validation are later gates.
Initial SDR 8-bit uses `RangeScale = 1`; this is not a claim of limited-range
equivalence, which must be checked with encoder/reference/color evidence later.
The standalone actual-device test checks only pipeline creation and limits; an
unavailable supported GPU is an explicit skip, not a pass. No runtime corpus,
decode dispatch, pixel validation or local build/runtime result is claimed here.

## Decoder/v1 host implementation

`MLPyrowaveMetalDecoder.mm` adapts the same pinned `metal/pyrowave_decoder.mm`
regions `DequantPush`, `IdwtPush`, `encode_dequant`, `encode_idwt_dispatch` and
`encode_idwt`, plus `metal/pyrowave_common.mm`'s `WaveletPyramid::init` view layout.
These host files carry Copyright (c) 2026 Hans-Kristian Arntzen, SPDX MIT;
the adapter preserves attribution and the complete MIT notice above. Layout table
ordering also follows pinned `metal/pyrowave_bitstream.cpp`'s `BlockLayout::init`
(2025 Hans-Kristian Arntzen / 2026 AlkaidLab, MIT AND GPL-3.0-only).
No upstream parser, upload growth, blocking slot reuse or precision selection is
imported. Only immutable CPU-validated frames enter FP32 R32Float reconstruction;
final private R8Unorm planes retain the SDR `RangeScale = 1` baseline.

Dequant batches bands per component/level: grid.z is 3 (bands 1..3) at levels
0..3 and 4 (bands 0..3) at level 4, reducing 42 dispatches to 13; IDWT stays 13.
The standalone decoder test manually compares per-band grid.z=1 with batching,
using the same pipeline/input/offsets and private R32Float readbacks for 3/4 bands,
4x4/65x33 geometry, sparse blocks and nonzero signed records. These are bytewise
batching-equivalence checks, NOT encoder/IDWT differential goldens. Execution is
CI-only per tests/pyrowave/README.md; no GPU result or speedup is claimed here.

One in-flight GPU slot and one coordinator-pending CPU frame are the intended
integration bound. The backend alone commits the supplied renderer queue buffer;
the synchronous presentation borrow must encode every last reader there, without
retaining planes/buffer, committing, enqueueing or using another queue. Completion
retains private retirement state, not decoder/frame/UI, until all readers complete.
Separately, a per-submit shared/tracked no-copy Metal resource owns a validated
pooled frame and its pool until resource retirement; its deallocator drops the
owner, never frees bytes. Command-buffer retention, not only a completion callback,
prevents premature slot reuse. No decoder/UI cycle or post-validation CPU writes.
Non-pooled input or any alias failure uses the fixed copy fallback; offsets copy
on both paths. Helper lifetime tests and pooled sparse GPU smoke await CI; neither
is independent image proof. macOS compile/lifetime/GPU output remain unverified.
Two fixed tracked heaps still bound private textures and fallback uploads. The original v1
cap was 256 MiB; current session accounting has a 512 MiB hard ceiling, not a
full-cap allocation. It reserves 128 MiB strict reassembly including scratch, 32 MiB
validation peak, two CPU owners (each 16 MiB + 16-byte guard + offset table + 4096
bytes), and 1 MiB bookkeeping, plus all three payload slots (48 MiB + 192 KiB),
including inactive slots. Keeping the reassembly/CPU-owner terms deliberately
conservatively double-counts payload storage; actual heap sizes are then charged.
Views alias storage.
This is not a process-RSS/driver-cache/global-memory guarantee. Configuration is
immutable: callers must retire/drain old instances before same-session replacement.
No network/settings/renderer wiring or throughput promise is added. App compilation
is pending a later remote build; GPU correctness and live-stream validation are
reserved to the user on hardware, not proved by static inspection or submission.
